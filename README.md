# RoleBasedRecords

## Исходная задача

Нужно реализовать приложение, которое реализует эти требования:

- структуру ASP.NET приложение;
- разбиение приложения на слои;
- REST ASP.NET;
- middleware для авторизации;
- PostgreSQL и EF Core.

Таблицы:

1. таблица с авторизацией пользователей;
2. таблица с любыми данными.

Нужно уметь разделять пользователей по ролям, используя паттерн Strategy. В зависимости от роли пользователя нужно выбирать разные поля из БД при помощи паттерна Strategy.

Нужен метод `logout`. Он разлогинивает пользователя со всех активных сессий.

## Быстрый запуск

Понадобятся:

- Windows;
- запущенный Docker Desktop.

После клонирования репозитория откройте его папку и запустите:

```text
RUN.cmd
```

Скрипт сам создаст файл `.env` со случайными локальными паролями, соберёт контейнер API, запустит PostgreSQL, применит миграции и откроет Swagger. Устанавливать .NET SDK и PostgreSQL отдельно не нужно. При первом запуске Docker загрузит необходимые образы, поэтому он может занять несколько минут.

После запуска откроется Swagger:

```text
http://localhost:5279/swagger
```

Окно `RUN.cmd` после успешного запуска можно закрыть. Чтобы остановить API и PostgreSQL, запустите `STOP.cmd`. Данные БД сохранятся между запусками.

Если порт `5279` занят, измените значение `API_PORT` в созданном файле `.env` и снова запустите `RUN.cmd`.

## Как протестировать

Для выбора роли - нужно выбрать роль в выпадающем списке метода `login`.

После успешного `login` Swagger автоматически использует полученный токен в следующих запросах — вручную копировать его в **Authorize** не нужно.

Все проверки можно выполнить в Swagger.

1. Откройте `POST /api/auth/login`, нажмите **Try it out** и войдите как `user`
2. Выполните `GET /api/records`. Пользователь с ролью `User` получит только поля `id`, `name` и `publicDescription`.
3. Выполните `POST /api/auth/logout`.
4. Снова вызовите `GET /api/records`. Ответ `401 Unauthorized` означает, что выданный токен больше не действует.
5. Повторите вход как `admin`
6. Снова выполните `GET /api/records`. У `Admin` дополнительно будут поля `internalComment`, `costPrice`, `createdByUserId` и `createdAt`.



Чтобы отдельно проверить завершение всех сессий, откройте Swagger в обычном и приватном окнах браузера. Войдите под одним пользователем в обоих окнах, выполните `logout` в одном из них, а затем вызовите `GET /api/records` во втором. API должен вернуть `401 Unauthorized`.

Доступные методы:


| Метод  | URL                | Назначение                                   |
| ------ | ------------------ | -------------------------------------------- |
| `POST` | `/api/auth/login`  | Вход и получение JWT                         |
| `POST` | `/api/auth/logout` | Завершение всех активных сессий пользователя |
| `GET`  | `/api/records`     | Получение полей записи в зависимости от роли |
